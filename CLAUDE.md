# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

qslides is a Windows-only desktop photo frame: a frameless widget that shows a slideshow of the pictures and silent videos found in the folders of its library (subfolders included). Written in Rust with egui/eframe 0.36 (glow). Priorities: a small, quiet widget (little CPU between slides), Windows' own codecs (WIC for pictures, Media Foundation for videos, nothing shipped beside the exe), start-up speed. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone, no imperatives).

The display name and the identifier are the same, `qslides`: the UI, the window title, the READMEs, the installer, `%APPDATA%\qslides`, `%LOCALAPPDATA%\Programs\qslides`, `qslides_<ver>_Setup.exe`, the Cargo package, `qslides.exe`, the GitHub repo `Fan4Metal/qslides`, the Run value.

The original spec (`local/SPEC.md`, not committed): a desktop widget with a library of several folders scanned recursively, a slideshow of pictures and videos without sound, a borderless window with size presets of aspect ratios; start with Windows, always on top, slide time and order, tray only (no taskbar button). Decisions taken with the user: videos play to the end or as long as a picture (a setting); orders by name, by date, random; a picture fits whole or fills the window (a setting, fit by default).

## Commands

```
uv run build.py                  # closes a qslides.exe running from target\, then cargo build --release
cargo build --release            # target\release\qslides.exe (fat LTO)
cargo test                       # unit tests (playlist orders, natural sort, scan, EXIF orientation, WIC decoding, menu, settings, window proportions)
cargo clippy --all-targets       # must stay warning-free
cargo fmt                        # width 100
python tools/make_release.py     # tests, release build, dist\qslides_<ver>_Setup.exe (Inno Setup 6, tools/setup.iss) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy
.\target\release\qslides.exe --export-icon file.ico   # the app icon for the installer / the README
$env:RUST_LOG="qslides=debug"    # what is shown and decoded, with timings (stderr)
$env:QSLIDES_VIDEO="C:\v.mp4"; cargo test video_file -- --ignored --nocapture   # decode a real video, print frames and speed
$env:QSLIDES_VIDEO="C:\v.mp4"; cargo test video_in_pieces -- --ignored --nocapture   # a video longer than 7 s shown for 6 s in 3 pieces
$env:QSLIDES_VIDEO="C:\v.ts"; cargo test video_loops -- --ignored --nocapture   # a looped video has no stop at its seam
$env:QSLIDES_IMAGE="C:\p.jpg"; cargo test --release image_file -- --ignored --nocapture   # time decoding a real picture
$env:QSLIDES_IMAGE="C:\p.jpg"; cargo test date_of_a_file -- --ignored --nocapture   # the date taken of a real photo (or QSLIDES_VIDEO)
cargo test --release sorting_a_large_library -- --ignored --nocapture   # 100 000 files put in order
cargo test update -- --ignored   # asks GitHub for the latest release for real
```

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files; the tag must equal the version in `Cargo.toml`. Creating or pushing a tag publishes a public release, so do it only when the user asks. `tools/setup.iss` installs per user and removes the Run value on uninstallation. `.cargo/config.toml` links the CRT statically. These scripts mirror those of disk_flashlight, qview, qrec and metalmd; keep them in step.

Trying a change: `cargo test` and `cargo clippy --all-targets`, then `uv run build.py` and run `target\release\qslides.exe`; the user runs the widget all day, so finish with `python tools/make_release.py --no-tests --install` (it closes the installed copy first, so its settings are saved). To try a library without touching the user's settings, copy the exe into a folder with an `app.ron` (portable mode, may hold `{"interval": "3", "video": "interval"}`) and a `library.txt` naming a test folder.

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `qslides.exe` locks the release binary; `build.py` closes it first. Heredocs containing Rust code break the Bash tool; write source files with the Write tool.

## Architecture

- **`main.rs`**: arguments (`--export-icon`, `--version`, `--help`), the panic hook, one instance (`instance::forward`), the library read and its scan started before the window is made, `NativeOptions` (frameless, resizable, drag and drop, min 120x90, default 480x320), `eframe::run_native`.
- **`app.rs`**: the eframe `App`. One slide on the screen (`current`: a picture's texture or a playing video) and the next one getting ready (`upcoming`: the loader's job, or a video started with its first frame awaited), so slides change at once with a 0.7 s cross-fade (the old slide painted whole under the new one, darkened only outside it, `outside`: fading both dimmed the middle of the change by a quarter). `step` counts moves through the playlist; a slide and the upcoming one carry their step, which tells "the next one" from "the one the show waits for" (`wanted`, `install`). The slide's `Clock` leaves pauses out. Frame order matters: the video is pumped before `advance_if_due`, so its end moves the show on in the same frame (it used to wait for an unrelated repaint), and pumped again after `install`, since a waiting decoder thread asks for no repaint. Repaints are scheduled with `request_repaint_after` (the slide's remaining time, the next video frame, the buttons' fade), so a picture on the screen costs nothing. `library` keeps the last scan's files of all kinds; `refill` gives the playlist those of `kinds` (after a scan and when the menu's **Show** switches change), the slide on the screen kept if it is still among them. The caption (`show::Caption`, a set of `CaptionPart`s switched on separately, joined by " · "; `paint_caption`, bottom left, on a dark band, cut with an ellipsis) comes in with its slide and gives way to the buttons; its date comes from `dates.rs`, asked for the slide shown and the upcoming one. Input: drag anywhere moves the window (`frameless::drag_area`), edges resize it, a right click opens the menu (on the button's release however the pointer moved, as metalmpv's: egui's `secondary_clicked` was lost past 6 points), a double click or Enter opens the file, the wheel and the arrows go through the files, Space pauses, F1 About, F5 rescans, Ctrl+O adds a folder, folders dropped on the window join the library. The Previous/Pause/Next buttons fade in while the pointer moves, and so do the file's buttons in the top left corner (Open, Show in its folder; moved there from the menu at the user's wish, kept while the pointer rests on them; the pause mark shows there when they and the bottom buttons are away) and the cross in the top right corner that ends the program (`ui::close_button`, red under the pointer, kept while the pointer rests on it; also over the start screen). The menu has no Exit, at the user's wish.
- **`library.rs`**: the folders (`library.txt` next to the settings file, one per line, kept apart from the settings as user data), the recursive scan on a thread (hidden/system folders and folder links/junctions skipped by `is_symlink`, a name-surrogate tag: OneDrive's files and folders are reparse points too and are scanned; a file found twice, in nested library folders, listed once; `Scanned::unreachable`, the library folders that could not be read, which `App` scans for again after 30 s, doubling, five times, marks in the menu and names on the start screen), the extensions, natural path order (Explorer's: digit runs as numbers, folder by folder; `sort_key` made once a sort, the components in lowercase joined by NUL, and `key_cmp` allocating nothing: allocating in each comparison, 100 000 files took 1.8 s on the UI thread). `library.txt` is read with a BOM, as UTF-16 or in the ANSI code page (Notepad's encodings), written as UTF-8.
- **`show.rs`**: the choices (order, fit, video length, aspect presets, intervals) and the `Playlist`: name order keeps the library's folder order, date order by modification time, random is a Fisher–Yates shuffle per round (xorshift, no crate) that never starts a round with the file just shown; the next round is shuffled ahead (its first file is decoded before the round ends) and the round before is kept for Previous. A file that cannot be decoded is dropped from the playlist until the next scan; `len`/`is_empty` count the show, not the library (`all_failed`: the library has files, none could be shown, said on the start screen).
- **`media.rs`**: WIC decoding (`windows` crate) scaled down to the monitor's long side with the Fant scaler, EXIF orientation applied by hand on the scaled pixels (`orient`; WIC's flip-rotator order is not documented); Media Foundation source reader with advanced video processing: only the first video stream selected (no sound ever), decoded and scaled on the graphics card (DXVA: a D3D11 device with video support in an `IMFDXGIDeviceManager`, `MF_SOURCE_READER_D3D_MANAGER` and hardware transforms; on the processor when the card or driver refuses), RGB32 output scaled by the video processor to fit the window (its longer side, twice that when filling, rounded up to a step of `app::VIDEO_SIDES`, 640 to 1920), at most 30 frames a second sent (`FRAME_STEP`: the others are decoded but not copied off the card; an iPhone 4K60 HEVC Main 10 video played far too slowly on the processor on another computer, and mpv, as in metalmpv, was ruled out as too large a dependency), frames through a `sync_channel(3)` (the thread waits while the UI does not take them; dropping `Video` stops it), a video longer than its time (`Plan`: the interval, or `video_limit` when shown to its end) shown in pieces (`pieces`: equal ones, the first at the start, the last ending at the end, none under 2 s; the duration is `MF_PD_DURATION`; each piece a seek, the frames before its start dropped, `VideoMsg::Cut` before its first frame, which `Playing::pump` puts into a new texture so that the old one fades out as a slide does; the decoder sends `End` after the last, the clock waits `PIECES_GRACE` more; `video_in_pieces`, ignored, `QSLIDES_VIDEO`; seeking took about 0.4 s a piece), a looped video's times keep growing (each round offset by its own first frame's time, which is not 0 in camera MPEG-TS: `video_loops`); when the UI is behind, only the last of the frames due is set into the texture. Phone videos with a rotation (`MF_MT_VIDEO_ROTATION`) come out upright from the source reader as it is (the user saw an iPhone HEVC clip, 3840x2160 at −90°, upright). A 4K60 H.264 clip decodes, scaled to 1920 and every other frame copied out, at 215 frames a second on the card against 150 on the processor (`video_gpu_and_cpu`, ignored, `QSLIDES_VIDEO`); this machine has no HEVC extension to try 10-bit HEVC.
- **`dates.rs`**: the date a file was taken for the caption, through the shell's property system (`SHGetPropertyStoreFromParsingName`: `System.Photo.DateTaken`, the EXIF DateTimeOriginal whatever the format, then `System.Media.DateEncoded` for videos), turned from UTC into the local day; on a thread with COM started at the first request, only for the files shown, kept in a map forgotten past 10 000. A JPEG took 37 ms, an MP4 7 ms (`date_of_a_file`, ignored); read at the scan for 100 000 files it would be far too slow.
- **`loader.rs`**: one thread with COM decodes the next picture and makes its texture (mipmapped: the window is usually much smaller than the screen); only the latest request counts.
- **`menu.rs`**: the widget's menu, drawn by egui in a window of its own (`MenuWindow`: an immediate viewport without decorations, taskbar button or resizing, always on top, owned by the widget through `ui::OwnWindow`), because an egui popup is a layer of its window and a small widget would cut it. A native Win32 menu was the first version; the user asked for egui's look and a slider. It opens at the pointer (a right click on the widget), placed in pixels every frame by `win::place_popup` (flipped left or up at the work area's edges), its height measured from its content (`ui.vertical(…).response`: the `CentralPanel`'s own rect is the whole window). It closes when it loses the focus after having had it, on Esc, and after a command for which `Cmd::closes_menu` is true; settings and the show's buttons leave it open. `content` returns `Cmd`s, which `App::ui` runs after the viewport's closure (the closure cannot borrow the app). The interval slider moves over the steps of `show::INTERVALS` (1 s to 1 h, finer at the short end); the top row shows the place in the show (`Playlist::position`, files that failed are no longer counted) and, at its right, About (an "i") and a cross that closes the menu (`Cmd::Close`), where the file's buttons were; a newer release is offered at the top. `the_menu_draws_and_asks_for_nothing_by_itself` draws it headless.
- **`dialog.rs`**: the folder dialog (`rfd`) on a thread of its own, owned by the widget through a hand-made `HasWindowHandle` (metalmpv's `dialog.rs`, the folder only); its answer is taken each frame in `App::ui`. Called in a frame, the dialog's own message loop stopped the show and the video while it was open (the user noticed).
- **`tray.rs`**: the notification-area icon while "Only in the tray" is on (metalamp's); its messages arrive in the window subclass. Started with Windows, the shell may refuse the icon (Explorer not ready): `App::make_tray` makes it on `TaskbarCreated` and asks again every 3 s while it is missing (without it the widget had neither a taskbar button nor an icon); an icon already there after a refused `NIM_ADD` counts as added. A left click brings the widget forward; the right button opens a native popup menu (`tray::menu`, `TrackPopupMenuEx` in the window procedure, as metalamp's tray menu): qslides (bold, brings the widget forward) and Exit (queued as `Hooked::Exit`, a viewport close) — the user's wish, since the egui menu has no Exit. The egui menu opens only from the widget's right click. Posting `WM_APP + 0x51` with `lparam = WM_CONTEXTMENU` and the point in `wparam` to the widget opens the native tray menu (modal; Esc closes it).
- **`win.rs`**: the family's helpers plus the window subclass (`hook_window`: tray clicks and menu, `TaskbarCreated`, `TaskbarButtonCreated`, the session locked (`WM_WTSSESSION_CHANGE`) and the display off (`GUID_CONSOLE_DISPLAY_STATE`), which hold the show as a pause apart from the user's (`App::halted`), and `WM_SIZING` keeping the aspect preset while the window is sized, not below `MIN_SIZE` in the window's pixels), the window's layer (`show::Layer`: normal, always on top, on the desktop; the two exclude each other): on the desktop winit's `AlwaysOnBottom` puts it at the bottom once and `WM_WINDOWPOSCHANGING` turns any z-order change (a click activating it) back to `HWND_BOTTOM`, unless the user raised it (`raise`: the tray icon; `mark_raised`: a second start), which lasts until `WM_ACTIVATEAPP` says another program has the focus; always on top, the yield to full-screen programs (`set_yield`: a 500 ms `WM_TIMER` handled in the subclass, so nothing is painted for it; `full_screen_in_front`: the foreground window of another program on the widget's monitor covering all of it and not a maximized captioned window, the desktop's `WorkerW`/`Progman` left out, or `SHQueryUserNotificationState` saying D3D full screen or presentation mode; the widget is put just after that window, which drops its topmost place, and back to `HWND_TOPMOST` when it is gone; winit keeps believing it is topmost, so `set_yield(false)` restores it before a level change), `reshaped` (a preset applied: same area and centre, inside the work area), the taskbar button through `ITaskbarList` (winit takes `with_taskbar` only at creation; Explorer re-adds the button when eframe shows the window or Explorer restarts, so it is deleted again on `TaskbarButtonCreated` and on uncloak), the Run key (`autostart` counts only a value naming this exe, so an installed and a portable copy do not mistake each other's), `show_in_folder`, `screen_side`.
- **`instance.rs`**: one widget per exe (metalamp's without paths): a second start brings the first forward and exits; names carry a hash of the exe path.
- **`frameless.rs`**: metalamp's drag area and resize strips for the frameless window (DWM keeps its shadow; Windows 11 rounds the corners, `win::round_corners`).
- **`border.rs`**: the picture frame painted along the window's edges (`Border`: none, black, white, graphite, wood, mat; `border_width` 1..10 steps of 1.5 % of the shorter side), the slide placed in its opening (`opening`). A moulding seen from the front, lit from the top left: four mitred rails, each bands across its width (`stops`, the profile) blended by one mesh with vertex colours (no texture), the top rail lightest (`SIDE_SHADE`), the frame's shadow on what it holds; wood's grain is bands of a fixed pseudo-random shade. The mat is a thin moulding round a flat board that also fills the bars of a picture fitted whole (`ground`, also the colour the cross-fade darkens the old picture's bars to) with a white bevel round the picture. None round the start screen.
- **`caption.rs`**: the window handle, `DWMWA_USE_IMMERSIVE_DARK_MODE` (About's caption), `DWMWA_CLOAK` (no white flash at start: cloaked for three painted frames).
- **`ui/`**: `app_icon`, `round_button` (the buttons over the picture), `OwnWindow` (metalamp's: a viewport made hidden, found by title, cloaked, owned by the widget, centred over it or placed by its caller, uncloaked after three frames; About and the menu), `icon_button`; `ui/about.rs` About as its own window (the widget is often smaller than About), its height measured from its content, always on top when the widget is (owned by a topmost widget, a plain window was still covered by it) and modal: `App::ui` disables the widget (`win::enable`) while it is open, so a click on the widget brings About forward; `ui/start.rs` the start screen scaled to the window (name and version only when the window is at least 220 points high); `ui/icons.rs` the family's painted icons.
- **`icon.rs`**: the app icon, a modern photo frame (it was a gilded one, which the user found old-fashioned): a slim graphite profile with rounded corners, a light line along its top edge, a wide white mat with a fine bevel, a bright flat landscape (blue-to-warm sky, a low sun, layered hills) under a glint of glass. Below 40 px the mat is a pixel-wide line and the glint and bevel go; the profile is kept at least 1.5 px. Edges are smoothed over one pixel of each layer (`sample(x, y, px)`).
- **`update.rs`**: the opt-in update check (off by default, once a day at start-up, "Check now" in About).

## Conventions

- Every user-visible string goes through `tr!("English", "Русский")` (`i18n.rs`). Log messages, CLI output and technical errors stay English.
- Persisted state (eframe storage, `app.ron`): `language` (`system`/`en`/`ru`), `check_updates`, `last_update_check` (Unix seconds), `interval` (seconds, 1..86400), `order` (`name`/`date`/`random`), `kinds` (`pictures`/`videos` joined by `+`, never none: `show::Kinds` keeps the last one on), `fit` (`fit`/`fill`), `border` (`none`/`black`/`white`/`graphite`/`wood`/`mat`), `border_width` (1..10), `video` (`whole`/`interval`), `video_limit` (seconds a video shown to its end may take, 0: none; the menu's one **Length** slider sets `video` and `video_limit` together over `show::VIDEO_TIMES`: as pictures, 10 s to 1 h, whole), `video_pieces` (1..10), `caption` (the parts switched on, `folder`/`name`/`date` joined by `+`, or `none`; a single part, as saved before, reads too), `aspect` (`free` or `W:H` of `show::ASPECTS`), `layer` (`normal`/`top`/`desktop`; an older `on_top = true` reads as `top` and the key is removed when saved), `yield_full_screen` (on by default), `tray_only`, `last_file` (the show resumes from it); eframe persists the window geometry. The folders are in `library.txt`; starting with Windows is the `qslides` value of `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. The theme is always dark (a photo frame), so there is no theme setting.
- The version comes from `Cargo.toml` (`main::VERSION`, shown in About). Between releases it is the next version with `-dev`; `build.rs` appends `git describe --tags --always`. Release: drop `-dev`, commit `Version X.Y.Z`, tag `vX.Y.Z`, then set `X.Y.(Z+1)-dev`.
- The release profile has `panic = "abort"` and no console: a panic shows a message box (`main::install_panic_hook`). Sizes read from files may be 0 (checked in `media.rs`); pictures are capped by `max_texture_side`.
- Commits in this repository end with a `Co-Authored-By:` trailer naming the Claude model doing the work, e.g. `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (the user's choice for this repo).
- GUI checks: the OpenGL client area cannot be captured with `PrintWindow` on an NVIDIA machine, but `Graphics.CopyFromScreen` of the window's rectangle from a DPI-aware process shows it; keys can be posted with `PostMessage(WM_KEYDOWN/WM_KEYUP)` (F1 opens About; the widget's menu opens only on a right click; the tray message opens the native tray menu, see `tray.rs`). A launched window takes the focus: warn the user before launching test windows and before any simulated input, and close test windows with `taskkill /PID` (WM_CLOSE, which saves the settings). On the desktop, `taskkill` did not close the widget (it seems to pick the process's highest window, winit's hidden thread window then): post WM_CLOSE to all the process's windows, as `make_release.py`'s `post_close` does. The z-order can be listed with `GetTopWindow`/`GetWindow(GW_HWNDNEXT)`; a full-screen borderless WinForms form activated in front shows the yield (`giving way to a full-screen window` in the log). Mouse behaviour (dragging, sizing, clicks in the menu) is checked by the user. A second start of the same exe only brings the first forward: close an earlier test copy before starting a new one.
